# morse_keyer 半二重交信(QSO)機能 設計

対象スケッチ: `sketches/morse_keyer/morse_keyer.ino`(UNO R4 WiFi)

## 目的

1個の電鍵で打ったモールスを解読・表示する既存機能に、運用上の手順信号
(prosign)を検出して「相手局(BOT)と半二重で交信しているふう」を出す機能を足す。
prosign に応じて通信状態を遷移させ、BOT がモールス(LED + ブザー)で定型応答や
エコーを打ち返す。

## 採用する prosign(5つ)

prosign は構成文字を文字間ギャップ無し(要素間=1単位)で繋げて打つため、
1つの長い符号列として確定する。確定した符号列を
**prosign 表 → 通常文字(A-Z/0-9)→ `?`** の順で照合する。

| prosign | 符号       | 意味             | BOT の挙動                         |
|---------|-----------|------------------|------------------------------------|
| `KA`    | `-.-.-`   | 交信開始         | `QRV`(どうぞ)を打ち返す           |
| `AR`    | `.-.-.`   | 通信文終わり     | `R`(了解)を打ち返す               |
| `K`     | `-.-`     | どうぞ(送信権)  | 直前メッセージをエコーで打ち返す   |
| `SK`    | `...-.-`  | 交信終了         | `73`(さよなら)→ 状態 IDLE へ      |
| `BT`    | `-...-`   | 区切り           | message に空白挿入、BOT 応答なし   |

`SYM_MAX` を 7 → 10 に拡張(prosign は最長6シンボル)。

### prosign `K`(over)と文字 K の衝突

`K` の符号 `-.-` は文字 K と同一。本物のモールスでも符号上は区別不能で、
運用では「送信の最後に単独で打たれた K」を文脈・位置で over と解釈している。
これに倣い、次のルールで判定する:

- **message が空、または末尾がスペース(=語境界)の状態で、単独の `-.-` が
  1文字として確定したとき = over(送信権を渡す)**
- それ以外の `-.-` は文字 K として通常どおり message に蓄積する

## 状態マシン(半二重)

```
IDLE ──打鍵──▶ ME_SENDING ──prosign確定──▶ BOT_SENDING ──送出完了──▶ IDLE
                   │(通常文字)
                   └─ message へ蓄積(IDLE/ME_SENDING を行き来)
```

- `IDLE`: 待機。電鍵を叩くと `ME_SENDING` へ。
- `ME_SENDING`: 自分が符号入力中。通常文字は message へ蓄積。prosign 確定で
  対応する BOT 応答を組み立て `BOT_SENDING` へ。
- `BOT_SENDING`: BOT が応答符号を送出中。**ノンブロッキング**で1要素ずつ送る。
  送出中の電鍵入力は無視(本物の半二重に倣う)。送出完了で `IDLE` へ。

## BOT のモールス送出(ノンブロッキング)

`delay()` は使わず、`loop()` 内のステートマシンで `millis()` 基準に1要素ずつ送出する。
電鍵の解読ロジックを止めないことが必須。

- 単位長 `UNIT_MS`(例 120ms)を基準に:
  - dot = 1単位 ON、dash = 3単位 ON
  - 要素間 = 1単位 OFF、文字間 = 3単位 OFF、語間 = 7単位 OFF
- ON 中は LED(D4)+ ブザー(D5, `tone()`)を鳴らす(自分の打鍵サイドトーンと共用)。
- 送出キュー: 応答テキスト(例 `"QRV"`)を文字 → 符号 → ドット/ダッシュ列に展開し、
  インデックスを進めながら送る。

## LCD レイアウト(案A: 会話ログ型)

- 1行目: `ME:` + 自分の確定テキスト末尾(13字)
- 2行目: 状態で切替
  - `IDLE` / `ME_SENDING`: `>` + 入力中符号 + 右端にプレビュー1字(現状維持)
  - `BOT_SENDING`: `BOT:` + 送出中テキスト(打つに連れ1字ずつ増える=送信中の演出)

毎回フル幅16字で上書きし `clear()` を使わない(チラつき抑制、既存方針を踏襲)。

## Serial ログ

既存の `mark` / `letter` に加えて状態・BOT 動作を出力する:

- `prosign KA` / `prosign AR` …(prosign 確定時)
- `state ME->BOT` / `state BOT->IDLE`(状態遷移時)
- `bot-send QRV`(BOT 送出開始時)

`docs/` の Web Serial ダッシュボード側でも拾えるようにする。

## クリアボタン(D3)の扱い

既存どおり全消去。加えて状態を `IDLE` に戻し、BOT 送出中なら中断する。

## タイミング定数(調整可)

| 定数             | 既定値  | 用途                          |
|------------------|--------|-------------------------------|
| `DASH_MS`        | 250    | 押下時間がこれ以上で `-`       |
| `LETTER_GAP_MS`  | 700    | この無音で1文字/符号列確定     |
| `WORD_GAP_MS`    | 1500   | この無音で語区切り(空白)      |
| `UNIT_MS`        | 120    | BOT 送出の1単位長(新規)       |

## 非対象(YAGNI)

- `SOS` の警報点滅など prosign ごとの特殊演出(今回の交信ごっこには不要)
- 複数局・コールサイン管理
- WiFi 連携(本機能はローカル完結)
